# 🚛 만차

### 콜 1건이 아니라, 차주의 하루 1일을 거래한다

차주가 "내일 내 트럭의 하루"를 통째로 시장에 등록하면,<br/>
AI 에이전트가 밤사이 오더를 조합해 공차 구간 없는 '하루 패키지'를 설계하고<br/>
아침 음성 브리핑으로 근거와 함께 제안하는 화물 운송 의사결정 지원 서비스

</div>
<br/>

## 📌 한 줄 소개

기존 화물 플랫폼이 "어떤 오더가 있는가"에 답한다면, **만차는 "내일 내 하루는 어떻게 완성되는가"에 답합니다.**
편도는 고정 계약, 귀로는 각자도생이던 화물차주의 하루 절반을 AI가 설계하고, 근거를 설명하며, 운행 중 돌발 상황엔 실시간으로 재조립합니다.

<br/>

## 🎯 문제 정의

- 국내 미들마일 시장은 약 30조 원 규모지만, 계약의 상당 부분이 여전히 전화 흥정과 수기로 이뤄짐
- 기존 플랫폼은 **탐색(오더 목록)**과 **정산**만 해결했을 뿐, "여러 오더 중 어떤 조합이 내 하루의 최선인가"는 여전히 차주 개인의 몫
- 개인(지입) 차주는 유류비·통행료·감가까지 스스로 부담하는 1인 사업자이지만, **개인 원가 기준으로 남는 장사인지** 계산해주는 도구는 없음

<br/>

## 👤 타겟

| 구분         | 대상                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| 세그먼트     | 회사 소속이 아닌 **개인(지입) 차주**                                       |
| 운행 패턴    | **고정 편도 + 유동 귀로** (나가는 길은 계약, 돌아오는 길은 매일 시장 조달) |
| 첫 타겟 노선 | **경부축(수도권↔부산·경남) 왕복, 5톤 카고**                                |

<br/>

## 🕐 서비스 구조: 밤의 설계 → 아침의 브리핑 → 낮의 재조립 → 저녁의 복기

```
전날 밤        밤사이 (AI 파이프라인)                새벽              운행 중            운행 후
등록(오퍼)  →  스카우트 → 빌더 → 리스크예측기 → 감정사  →  음성 브리핑     →  실시간 재조립  →  복기 학습
차주 입력      오더 스캔   패키지 조합  자동 탈락 판정  근거     "왜?" 음성 문답     닫힌 질문 제안     성과 원인 분석
                                                    평가·보정
```

### AI 에이전트 4인방

| 에이전트          | 역할                                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| **스카우트**      | 시장 오더 수집, 경로·시간 창 기준 후보 필터링                                       |
| **빌더**          | 오더를 시공간 퍼즐로 조합해 패키지 2~3안 생성 (수익·주행거리·복귀시각 트레이드오프) |
| **리스크 예측기** | 화주별 취소·지연 확률 예측, 기준 초과 시 자동 탈락 판정 + 백업 오더 사전 확보       |
| **감정사**        | 개인 원가 + 대기·공차 비용으로 보정 평가 + **사람이 읽을 수 있는 근거 문장 생성**   |

### 음성 인터랙션 원칙

- **닫힌 질문 원칙**: 모든 발화는 예/아니오 또는 번호로 답 가능하게 설계 ("2안으로 할까요?")
- **되묻기 지원**: 차주가 음성으로 되물으면(예: "대기 시간이 왜 이렇게 길어?") STT로 인식한 질문 그대로 RAG 에이전트에게 질의해 답변

<br/>

## 🏗️ 기술 스택

| 영역      | 기술                                                                          |
| --------- | ----------------------------------------------------------------------------- |
| Frontend  | `React` · `TypeScript` · `TailwindCSS` · `Vite`                               |
| Backend   | `FastAPI`                                                                     |
| DB        | `SQLite` (해커톤 데모 규모)                                                   |
| AI        | `Gemini API` (패키지 평가·근거 문장 생성, 리스크 판단 근거 설명)              |
| 음성      | `Gemini TTS` / `STT` — 백엔드에서 프록시 호출 (프론트엔드에 API 키 노출 없음) |
| RAG       | 키워드 기반 질의응답 데모 (임베딩·벡터 검색은 추후 고도화 예정)               |
| 지도·경로 | 정적 이미지 mock (카카오맵 SDK 연동은 추후 예정)                              |
| 배포      | `Vercel` (Frontend) · `AWS EC2` (Backend)                                     |
